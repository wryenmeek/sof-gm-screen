# Google Drive v3 Bearer Fetch & IndexedDB Audio Pre-Caching

Audio Session Assets (10–25MB ambient loops, musical scores, and sound effects) are pre-cached into browser `IndexedDB` (`sof_audio_cache_v1`) by calling the Google Drive v3 REST API (`GET https://www.googleapis.com/drive/v3/files/<fileId>?alt=media`) directly from the client using a short-lived `Authorization: Bearer <token>` supplied by `ScriptApp.getOAuthToken()` in `Code.gs`. Standard Drive download URLs (`drive.google.com/uc?export=download`) and image CDN links (`lh3.googleusercontent.com`) omit CORS headers for audio files—blocking Web Audio API `decodeAudioData()` and `IndexedDB` storage—while tunneling multi-megabyte audio over `google.script.run` Base64 RPCs incurs 33% payload inflation and risks hitting the 50MB Apps Script response ceiling. Furthermore, because `google.script.run` is asynchronous and dropped by browsers during `window.beforeunload`, the Audio Timeline Sidecar (`session_audio_timeline.json`) writes events immediately to `localStorage` on every cue and flushes to Google Drive alongside Table Notes saves.
